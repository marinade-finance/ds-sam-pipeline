## Blacklist calculation moved into the auction pipeline

Design (minimal, shipped as local detached-HEAD commits, no push):
- ds-sam SDK (89b58af): added optional `blacklistFilePath` to DsSamConfig +
  `--blacklist-file` CLI option; `fetchBlacklist` reads that local file instead
  of fetching from `blacklistApiBaseUrl` when set. ~15 lines across config.ts /
  data-provider.ts / auction.cmd.ts. Verified: ds-sam-calc, ds-sam-sdk, and root
  all `tsc` clean (built calc→sdk→root; bun install since Node 18 blocks pnpm 10).
- ds-sam-pipeline evaluate-auction.yml (5538a36): checkout sam-blacklist →
  generate step (`pnpm main` + chromium) produces its blacklist.csv → the single
  online auction reads it via `--blacklist-file "$inputs_dir/blacklist.csv"` (so
  results.json reflects the fresh list) → PR republishes it at repo root
  `blacklist.csv` (real file, since raw.githubusercontent doesn't follow git
  symlinks). One PR = fresh auction + fresh blacklist.

Why the override was required, not just dropping a file in inputs/: verified the
pipeline runs `--inputs-source APIS` → `fetchSourceData()` fetches everything and
never reads inputs/; `--cache-inputs` then WRITES inputs/ (would overwrite a
pre-placed file). apply-auction.yml doesn't re-run the auction — it replays the
committed results.json. So the fresh blacklist has to feed that one online run.

Cleaned up: the standalone sam-blacklist pipeline (update-blacklist.yml and the
review/TODO/diary commits) is removed — sam-blacklist reset to origin/main
(efe6ce4). The pipeline now checks out sam-blacklist and runs its `pnpm main`
directly, so no separate scheduled workflow is needed there.
